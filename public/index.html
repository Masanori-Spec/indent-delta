Scope, supported syntax, and how to read the results
This is a bounded review of imported text and listed paths. It does not discover your repository, check file contents, prove whole-repository safety, or apply edits. Actual editor plugins may interpret properties differently.
Every ancestor .editorconfig must be supplied or explicitly listed as absent, until root = true or the virtual filesystem root. An absent entry is your assertion, not something the app verifies. An unknown ancestor produces an incomplete review, never a clean pass.
Values are computed by official editorconfig 3.0.2, with @one-ini/wasm 0.2.1. The reference fixtures are also checked against independent Python EditorConfig 0.17.1. unset remains a distinct directive; ∅ means absent. Derived tab_width is included. Matched sections show precedence order, not a guarantee about editor behavior.
This release accepts key = single-token scalar values, whole-line comments, and EditorConfig globs with *, **, ?, positive ASCII letter/digit character classes, simple comma-separated brace lists, and bounded integer ranges. For cross-core consistency, config directory paths cannot contain glob metacharacters; keys must be lowercase; comments must start in column one; numeric ranges must be ascending, unpadded integers. Non-ASCII whitespace outside comments, byte-order marks, control characters, lone CR line endings, empty sections, glob whitespace/#/;, escapes, extglobs, leading negation, nested braces, malformed input, and large expansion are rejected. Limits: 32 configs, 512 paths, 1 MiB config text, 8192 lines and 512 sections per config; globs up to 256 characters, ranges up to 100 values, expansion up to 256 alternatives including implicit globstar expansion, at most 6 globstars per glob, and at most 2048 total sections, 32 distinct properties (including derived fields), 1024 assertions, and 4096 matched-section trace entries, and 4096 unknown-ancestry entries. A cancellable worker stops processing after 8 seconds without a partial pass.
A “stay” assertion compares the full state of one property, including unset/absent. “change” requires a difference and may name the desired value. “value” checks the final value. Use <absent> for an expected missing property. Passing assertions only cover the checks you provided.
